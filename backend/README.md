# FamilyTasks API

Бэкенд для iOS-приложения семейных задач. FastAPI + SQLAlchemy 2.0 (async) + PostgreSQL.
Реализует контракт из [../API_CONTRACT.md](../API_CONTRACT.md).

## Запуск за пять минут

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env               # можно оставить как есть: поднимется на SQLite
alembic upgrade head               # создать схему
uvicorn app.main:app --reload
```

Документация: <http://127.0.0.1:8000/docs>, проверка живости: `GET /health`.

## Миграции

Схемой управляет Alembic. Приложение таблицы не создаёт — намеренно:
автосоздание тихо разводит рабочую базу с историей миграций.

```bash
alembic upgrade head                              # накатить
alembic revision --autogenerate -m "описание"     # после правки app/db/models.py
alembic downgrade -1                              # откатить одну
```

URL берётся из `DATABASE_URL` через `migrations/env.py`, в `alembic.ini` он
намеренно пуст — иначе легко случайно мигрировать не ту базу.
В Docker `alembic upgrade head` выполняется перед стартом uvicorn.

## Тесты

```bash
pytest -q
```

45 тестов в шести файлах:

- `test_contract.py` — **совпадение с контрактом iOS**: имена ключей в snake_case,
  значения enum (`in_progress`, а не `inProgress`), обязательный часовой пояс
  в датах, формат `detail` в ошибках, изоляция семей, ротация refresh-токена.
  Поменяете форму ответа — тест упадёт раньше, чем клиент.
- `test_rate_limiter_unit.py` — сам лимитер с поддельными часами: скольжение
  окна, обратный отсчёт `Retry-After`, независимость ключей, очистка памяти.
- `test_login_rate_limit.py` — блокировка через HTTP: в том числе что после
  блокировки не проходит даже верный пароль и что соседний аккаунт не задет.
- `test_refresh_token_cleanup.py` — просроченные токены удаляются, отозванные
  но ещё живые остаются.
- `test_visibility.py` — ребёнок не видит скрытое ни в списке, ни по прямой ссылке,
  не может прятать сам, и скрытую задачу на него нельзя назначить.
- `test_notes.py` — CRUD заметок, изоляция семей, порядок по дате изменения.

## Принятые решения

**Refresh-токен — не JWT, а случайная строка.** В базе лежит только SHA-256 хеш.
Это даёт то, чего JWT не умеет: мгновенный отзыв при `logout` и ротацию —
использованный токен гасится, а перехваченный перестаёт работать после первого
обращения настоящего владельца.

**Чужая задача — 404, а не 403.** 403 подтверждал бы, что запись с таким id
существует. Мелочь, но бесплатная.

**Логин не различает «нет пользователя» и «неверный пароль».** Иначе эндпоинт
превращается в способ проверить, кто зарегистрирован в сервисе.

**Все даты приводятся к UTC на входе и всегда отдаются со смещением.**
`ISO8601DateFormatter` на iOS требует часовой пояс: наивная строка
`2026-09-13T18:00:00` вернёт `nil`, и декодирование задачи упадёт целиком.
Плюс SQLite хранит `DATETIME` без смещения — без нормализации время «поехало» бы.

**PUT вместо PATCH для задачи.** Полная замена снимает неоднозначность
`"due_date": null` — «убрать срок» или «не менять».

**Лимит на `/auth/login` считает только неудачи.** Успешный вход не расходует
бюджет — иначе человек, заходящий в приложение каждое утро, однажды упёрся бы
в блокировку. Ограничений два: по аккаунту (5 за 15 мин — защита конкретного
пароля) и по IP (20 за 5 мин — защита от перебора по многим аккаунтам сразу).
Второй мягче: вся семья обычно сидит за одним домашним роутером.

Неудача записывается и для несуществующей почты. Иначе 429 приходил бы только
по зарегистрированным адресам — и сам лимит стал бы способом узнать,
кто есть в системе.

Успешный вход обнуляет счётчик аккаунта, но не IP: иначе атакующий со своим
аккаунтом сбрасывал бы себе лимит после каждой серии попыток.

Проверка стоит до обращения к базе и до `bcrypt` — хеширование намеренно
медленное, и перебор не должен нам его оплачивать.

**У регистрации счёт другой: считаются все попытки, включая успешные.**
Вред там наносит как раз успешное массовое создание аккаунтов, а не промахи.
Лимит — 5 в час на IP, и неудачные запросы (дубликат почты) тоже расходуют
бюджет, иначе он обходился бы заведомо невалидными запросами.

**Видимость — общий механизм для задач и заметок.** Одно поле `visibility`,
один набор правил в `app/api/access.py`, одни и те же тесты. Делать раздельно
значило бы написать проверки дважды и разойтись в поведении.

Enum, а не булев `is_private`: следом почти наверняка понадобится «личное, вижу
только я», а миграция `bool → enum` дороже, чем сразу enum.

Скрытая запись для ребёнка — **404, а не 403**. Ровно по той же причине, по которой
логин не различает «нет пользователя» и «неверный пароль».

Отдельное правило: задачу со значением `parents` нельзя назначить ребёнку.
Иначе она висела бы на человеке, который её не видит, и он не понимал бы,
почему с него что-то спрашивают.

**Заметки проще задач сознательно.** Нет статусов, сроков, исполнителей.
Редактировать может любой, кто видит: это общий блокнот семьи. Автор фиксируется
при создании и при правках не меняется.

**Просроченные refresh-токены удаляются попутно** при выдаче новой пары —
для семейного приложения отдельный планировщик избыточен, а работа ограничена
одним пользователем. Отозванные, но ещё не истёкшие записи остаются: по ним
позже можно будет ловить повторное использование украденного токена.

**`invite_code` в регистрации — расширение сверх контракта.** Поле необязательное,
iOS его не отправляет. Без кода создаётся новая семья (роль `parent`),
с кодом — вход в существующую (роль `child`). Так второй член семьи вообще
может появиться; при желании уберите и заведите отдельный экран приглашения.

## Деплой на VPS (Docker)

```bash
git clone <repo> /srv/familytasks && cd /srv/familytasks/backend
printf 'POSTGRES_PASSWORD=%s\nSECRET_KEY=%s\n' "$(openssl rand -hex 16)" "$(openssl rand -hex 32)" > .env
docker compose up -d --build
```

API поднимется на `127.0.0.1:8000`. Дальше nginx с TLS — конфиг в
[deploy/nginx.conf.example](deploy/nginx.conf.example), сертификат через
`certbot --nginx -d api.вашдомен.ru`.

Без Docker: юнит systemd в [deploy/familytasks.service](deploy/familytasks.service).

**HTTPS обязателен.** iOS App Transport Security блокирует обычный http,
а исключение в `Info.plist` — повод для отказа при ревью в App Store.
